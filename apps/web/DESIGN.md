# GOOBER product system — M2

The running M1 storefront was inspected through the product auditor's real 390px screenshot before implementation. The catalog started around 1170px because the introduction repeated its promise in a second large panel. Existing assets are the `g.` wordmark, forest green, navy ink and warm canvas. These remain the brand foundation.

M2 uses an editorial shop with Georgia display headings and system sans-serif controls. Fonts are installed system fallbacks, with no external requests or package additions. The shop introduction is compact; product discovery comes before the explanatory steps. Account and operations pages use compact sans-serif headings to make room for actual records.

- Tokens: canvas `#f8f7f3`, white surface, ink `#162b36`, forest action `#155d43`, muted `#55656b`, pale forest surfaces and high contrast control borders. Statuses have text as well as color.
- Type: 16px body; 12–14px supporting metadata; 24–32px section headings; restrained 36–58px shop display. Money uses tabular figures and existing exact formatting.
- Layout: 1200px readable maximum, 20/32px responsive gutters, 4/8px spacing rhythm. Two product columns on desktop, one on mobile. Account panels stack below 768px. Operations has an anchor index rather than hidden tabs.
- Controls: minimum 44px interactive height, visible 3px focus rings, specific pending labels, semantic labels, disabled SSR mutation controls until hydration, POST fallbacks retained.
- Feedback: passive request failures announce without taking focus; errors never imply that account access fixes a network problem. Empty states require a successful empty response. Recoverable next-page failures retain loaded records; authorization loss clears private records and pending work.
- Motion: only short color transitions; reduced motion removes these. No autoplay, ornamental loops, remote media, invented metrics or simulated success.

Core action names and API routes remain stable. Delivery reveal remains explicit and transient, cleared on order identity/session changes and hidden tabs. Fixture and live-disabled explanations stay visible and truthful.

Instructions read: repository AGENTS, installed Next server/client and navigation/TypeScript guides, UI UX Pro Max SKILL/pro-rules/quick-reference, fresh official Vercel Web Interface Guidelines, repository Playwright and Next security guidance. The skill's generic indigo palette and large marketing hero were rejected because they did not match the existing brand or observed catalog discovery problem. Browser acceptance is owned by the QA role; this design note does not claim an unrun check.

Additional React practice references read before resuming: server-auth-actions, derived-state-no-effect, move-effect-to-event, narrow effect dependencies and client event listeners. Existing server authorization remains authoritative; request generations and abort controllers prevent stale results, and page data derives from its current source identity. No SWR dependency or caching change was introduced.

## M3 storefront redesign — 29 October 2026

Reading this as a store for people comparing digital tools and services for work and creative projects. Its first job is to make the offer, product terms, price and next action clear. Variance6, motion1, density4: a distinctive composition with quiet interactions, preserving GOOBER rather than adopting another company's visual identity.

Before edits, the frontend engineer captured and visually inspected the current running GOOBER page on the process-verified port3000 at390/1280. Ignored evidence: `.local/m3/baseline/storefront-{390,1280}.png` and `observations.json`. The title/headline confirmed the old composition; the desktop journey panel repeated the offer, and the catalog was still loading after the short capture wait. These captures do not prove a healthy catalog or authenticated session. No owner screenshot was attached. The observed DOM did not include a Next devtools portal, so no black N was identified from these captures.

The new composition puts a literal offer beside the shopping task and account entry, then gives the catalog most of the page. The first screen offers browse, create account and sign in. A compact fixture disclosure explains synthetic products/funds, no real entitlement and disabled live purchasing. Product cards replace decorative Create/Explore strips with category, actual name/description, exact price and product/terms links. Twelve actual results render initially; Show more reveals more fetched records, while search/category filter the full response and retain URL state. Product details put terms and order follow-through beside the existing quote controls. The explanatory process follows the catalog as a real ordered sequence, without a second promotional panel.

Tokens retain forest `#155d43`, dark forest `#0d4430`, navy `#162b36`, warm canvas `#f8f7f3`, white surface and muted `#55656b`. Georgia carries the store display and product names; the installed system sans stack carries controls and body text. Display tracking is tighter than small supporting copy; reading measures stay bounded. Desktop uses an asymmetric introduction and three product columns, tablet two columns, mobile one. No remote fonts, image filler, token imports, blur layers, motion library or application package was added. Controls retain visible3px focus,44px minimum actions, native semantics and reduced-motion rules.

Loading, successful empty, filter-empty and unavailable states are separate. An unavailable catalog has one calm notice and a real, disabled-while-pending read retry. Product failure offers retry and a back route. Existing session/request generations, private-resource invalidation, server quote authority, exact formatting, idempotency and transient delivery handling are preserved. Create account links to the existing auth form's explicit create action; it does not submit until hydration and user action.

Skills read: installed frontend-design (Apache2), React practices, fresh Vercel Web Interface Guidelines, UI/UX guidance, project Apple design/typography/motion instructions after lead's owner-permission signal, and installed Next server/client, navigation and accessibility guides. Apple-derived restraint, purposeful feedback and optical hierarchy inform the work; broad token/library/Apple-clone recommendations are excluded by the GOOBER brief. Official HIG remains guidance, not an endorsement. Final after-state browser, accessibility and integration evidence is recorded by the lead/QA; this design note does not pre-claim those results.
