# Data model
Canonical Better Auth User/Session/Account/Verification + rate-limit records. User role is server-managed. Domain owner FKs refer to auth user ID.
Product holds a single supplier offer for M1, separate approved/published flags, provider/account/environment/mode, entitlement/region/delivery, observed stock and version; approval decisions are audited. Quotes snapshot immutable accepted economics and expire for acceptance only.
Wallet caches available/reserved NGN liabilities. LedgerAccount/Journal/Posting carry currency, exact BIGINT minor amounts, debit/credit direction and immutable operation identity. Deferred SQL triggers reject unbalanced/empty/unfinalized journals; immediate triggers protect finalized history. Runtime role is not schema owner.
Order has unique quote, independent fulfillment and money statuses plus locked aggregate counters. ProviderAttempt stores stable reference/body digest and permanent dispatch fence. Delivery holds authenticated contextual ciphertext/key/nonce/tag. PaymentIntent binds owner/ref/currency/amount/environment and reversal obligations. Inbox/outbox hold durable work identities and leases. Support/Review/Audit provide operational evidence.
PostgreSQL constraints and transaction tests, not Prisma types alone, prove integrity. Financial updates lock wallet then order and use bounded whole serializable retry. Supplier HTTP is outside transactions. Restore starts dispatch paused before reconciliations.
